# Global memory layer — one home for knowledge that is not about a codebase

status: approved

## Goal

Устранить причину расхождения правил: **память пишется по месту события, а не
по природе знания**. Правило о том, как ведётся работа, глобально по смыслу,
но оседает в проекте, где случился разговор. Вторая копия, уточнённая в другом
проекте, не знает о первой — и первая продолжает загружаться устаревшей.

Замер 2026-07-27: 255 правил `type: feedback` в 19 проектах; каждая процессная
тема живёт в 9-17 проектах; глобального слоя не существует. Подтверждённое
расхождение: `Nexus/feedback_model_tiering_sdd` (2026-07-02, «sonnet=исполнение
по детальным планам») против директивы 2026-07-21 («sonnet НЕ ВЫЗЫВАТЬ ни в
какой роли»). Второй экземпляр той же болезни — осиротевшее правило
`git-sync-workflow.md`, описывающее `~/continuous-claude`, которого на машине
нет.

Лечение — не в доставке, а в записи: у правила должно быть **одно** место.

## Non-goals

- **Не инжектить всё во все сессии.** Расхождение от этого не исчезает —
  противоречие просто попадает в контекст целиком, и редакции спорят внутри
  сессии.
- **Код не решает, глобальное знание или проектное.** Классификация — решение;
  механизм лишь требует, чтобы оно было объявлено явно.
- **Catalyst не хранит правила.** Плагин приносит знание о том, где лежит
  глобальная память, и механику работы с ней. Содержимое — пользовательское.
- **Синхронизация между машинами не является частью механизма.**

## Decisions

### M-01. Один фиксированный путь: `~/.claude/memory-global/`

Catalyst приносит знание об этом пути — и только. Ни переменных окружения, ни
файлов-указателей, ни автообнаружения: **несколько возможных мест сами по себе
являются проблемой**, ровно того же рода, что мы устраняем.

### M-02. Пустой или отсутствующий каталог — нормальное состояние

Нет каталога — нет инъекции, работа идёт дальше. Это не ошибка и не повод
что-либо блокировать: глобальная память нужна для качества решений, а не для
исполнения диспатча (в отличие от таблицы маршрутизации, которая гейту
необходима и потому fail-closed).

### M-03. Формат идентичен проектной памяти

Файл на один факт, frontmatter (`name`, `description`, `metadata.type`),
индекс `MEMORY.md` рядом. Единый формат — единый читатель; отличается только
этаж.

### M-04. Критерий: «как я работаю» против «факт о кодовой базе»

- **global** — процесс, тиринг, каналы, гейты, лексика, директивы. От кодовой
  базы не зависит.
- **project** — архитектура, соглашения, особенности сборки, продуктовые
  решения.

Проверочный вопрос: *если завтра этот проект исчезнет, правило останется
полезным?* Да — global, нет — project. Пограничные случаи (правило про
конкретный проект, чья причина общемашинная) решаются поштучно человеком.

### M-05. Поле `scope` обязательно для записей `type: feedback`

Отсутствие → отказ на записи. Симметрично dispatch-gate: механизм не
классифицирует за автора, но не даёт умолчанию сработать тихо.

### M-06. `scope: global` пишется в глобальный слой, не в проект

Проектная память может нести **указатель** на глобальное правило, но не его
самостоятельную редакцию: расхождение возникает именно там, где в проекте
лежит вторая версия текста. Указатель устареть не может.

### M-07. Доставка — индекс, не тела

SessionStart инжектит `MEMORY.md` глобального слоя тем же механизмом, каким
Catalyst инжектит `using-catalyst`. Тела правил читаются по требованию.

### M-08. Синхронизация — забота пользователя

Механизм её не выполняет. Если каталог является git-репозиторием, изменения
следует коммитить и пушить — это правило поведения, записанное в инструкции
слоя, а не функция плагина.

## must_haves

### truths

1. Запись `type: feedback` без поля `scope` не проходит: отказ называет
   недостающее поле.
2. Запись со `scope: global` оказывается в `~/.claude/memory-global/`, а не в
   проектном каталоге.
3. При непустом глобальном слое его индекс присутствует в контексте каждой
   сессии.
4. Отсутствующий или пустой каталог не вызывает ошибок и ничего не блокирует.
5. Ни одно правило не существует в двух самостоятельных редакциях: проектная
   запись на глобальную тему содержит указатель, а не текст правила.
6. Формат файлов глобального слоя идентичен проектному — один читатель
   обслуживает оба.

### artifacts

- Инструкция слоя в Catalyst: путь, критерий M-04, формат, правило M-08.
- Расширение `hooks/session-start`: инъекция индекса глобального слоя.
- Гейт записи: PreToolUse на Write по пути памяти — проверка `scope`.
- Тесты в `tests/scripts/` на truths 1-4, включая мутант-проверку (снять
  правило из механизма → тест обязан покраснеть).

### key_links

- `~/.claude/memory-global/` — сам слой.
- `hooks/session-start`, `hooks/hooks.json` — точки встройки.
- `docs/specs/2026-07-27-dispatch-gate-spec.md` — родственный механизм; тот же
  паттерн «явное объявление + отказ при умолчании».

## open / deferred

- **Миграция 255 существующих правил** — отдельная операция: сперва чистка
  расхождений (судья — пользователь, поштучно), затем перенос global-части.
  Механизм от неё не зависит и может встать раньше.
- **Отношения с `~/.claude/CLAUDE.md`** (132 строки, 35.7 KB, грузится всегда)
  не пересматривались. Он остаётся домом главных директив; слой — дополнение
  для того, что не заслуживает постоянной загрузки. Вопрос о переносе части
  CLAUDE.md в слой открыт.
- **Таблица маршрутизации** остаётся по D-08 первой спеки (дефолт в плагине,
  оверрайд пользователя) — режим отказа у неё другой (fail-closed), поэтому она
  за этим слоем не следует.
- **Записи из харнессов без хука** (kimi, opencode, crush, amp…) гейтом не
  покрыты: там `scope` соблюдается только дисциплиной.
